# 设计取舍

本文记录从“双机位导播产品”调整为“意图驱动实时媒体运行时”后的核心决策。旧导播
能力继续存在，但不再限制通用媒体类型、配置和发布节奏。

## 改变运行模型，而不是重写全部 codec

FFmpeg 最难复制的是几十年的格式、codec、优化和兼容积累。个人项目从这里正面竞争
会长期停留在低覆盖状态。`aimedia` 选择复用 libsrt、NVIDIA SDK 和 libxaac 等成熟
边界，把创新集中在媒体作业编译、有界执行、资源规划、故障恢复和 AI 接入。

代价是支持矩阵较窄；收益是每个支持组合可以给出可验证的运行和运维保证。

## 配置描述目标，编译器描述步骤

CLI 参数或手写节点图要求用户了解 codec、像素格式、硬件复制、队列和时间戳细节。
新架构把这些选择放入图编译器：用户声明输入和目标输出，`ExecutionPlan` 列出实际
节点、内存域、时钟域、队列策略和资源需求。

我们没有选择“配置即执行器”。计划与执行分离后，`explain`、资源准入、差分测试和
未来的多后端选择可以在打开真实资源前完成。代价是必须持续验证计划与运行时一致。

## 不是任意媒体图框架

GStreamer 已经证明通用插件图和格式协商很强大，也同时带来较高的组合复杂度。
`aimedia` 不允许任意节点无限组合；图编译器只生成经过支持矩阵验证的计划，并把
延迟、队列、内存复制和故障语义作为强制契约。

## Rust 内核与窄 FFI

时间戳、图编译、TS、队列、控制和监控使用 Rust。transport、codec 和 GPU 通过小型
原生边界接入。这样不可信媒体数据和资源生命周期主要由类型系统约束，同时避免为了
“纯 Rust”重写成熟网络和硬件实现。

公开 native 插件使用版本化 C ABI，不暴露不稳定 Rust ABI。原始视频帧的热路径不走
序列化插件接口。

## 内存域是一等契约

视频帧明确位于主机内存或 NVIDIA 显存。GPU surface 使用可自动释放的 lease，避免
decoder 仍被 encoder 或 analyzer 使用时提前回收。图编译器最终必须能指出上传、下载
或设备间复制，而不是只展示 codec 名称。

## 独立节目时钟

摄像机重启、网络重连、时间戳回绕和设备漂移都会破坏直接拼接。输入 PTS 只参与
映射；输出视频和音频由独立、单调的节目时钟生成。

这增加了重复帧、丢帧、采样计数和漂移校正工作，但换来切换输入和重连时可持续的
输出时间线。

## 所有媒体队列有界

直播不能靠不断堆积内存隐藏处理不足。实时主链使用背压或明确失败；允许过期的分析
数据使用丢旧数据或只保留最新样本。每条边都报告容量和水位。

队列策略属于执行计划，不能由节点随意创建无界 channel。

## 故障域属于图的一部分

transport 重连、decoder reset、输出断线、GPU OOM 和 AI 超时的影响范围不同。关键
节点失败时重建或终止作业；非关键节点失败只产生事件。输出断线期间丢弃历史编码包，
不能反向拖垮整个输入链路。

## AI 使用非阻塞 Tap

AI 获取抽样帧、PCM 和指标，返回带时间、置信度和有效期的事件。数据主链不等待 AI。
字幕、审核、人物识别、精彩片段和自动导播共用这一机制。

我们不把原始 GPU 帧通过 WebAssembly 组件来回传递；WebAssembly 只作为未来元数据和
策略插件候选，避免热路径复制。

## 自动导播降为可选策略

导播状态机、音频切换和 VLM contract 可以继续证明 AI 故障隔离，但它们不再决定
核心路线。策略只控制 timeline 选择，不能拥有 transport、codec 或节目时钟。

这样没有双机位需求的转码、协议桥接和 AI 用户也能直接采用运行时。

## Linux + NVIDIA 先形成可信基线

首发固定 Linux x86_64、Docker 和 NVIDIA，减少操作系统与硬件组合。普通 CPU CI 可
验证图、时间、队列、parser 和 fake backend；真实数据面在 GPU 容器验证。

项目不会静默使用 CPU codec 回退。缺少 SDK、驱动或硬件能力时应在资源准入阶段明确
拒绝。

## 市场协议按工作流增加

共同基线是 SRT/RTMP、H.264/AAC。中国大陆优先 RTSP 摄像机、H.265 输入和 RTMP/RTMPS
平台发布；海外优先 SRT/RTMP、YouTube/Twitch RTMPS，WHIP 需要真实服务验证。

没有用户证据时，不因为 FFmpeg 支持某格式就把它加入核心。
