# 为什么采用这套架构

本文记录第二阶段的主要设计决策。每项都包含采用理由、替代方案和代价，方便后来者判断哪些约束可以改变。

## 先替代一条工作流，而不是重写整个 FFmpeg

**决定**：Alpha 固定为两路 SRT/MPEG-TS H.264/AAC 输入和一路同格式输出。

FFmpeg 的价值来自几十年积累的格式、协议、滤镜和硬件适配。个人项目如果一开始追求同等覆盖，会长期停留在“每个模块只有一点”的状态。固定输入数量、容器和 codec 后，可以把同步、切镜、连续输出和故障恢复真正做完。

**没有选择**“先做通用转码框架”。代价是暂时不能处理 MP4、RTMP、AV1、字幕和任意滤镜；收益是支持矩阵可测试、问题边界清楚。

## Rust 内核与窄 FFI 边界

**决定**：时间戳、TS、同步、状态机、队列、控制协议和监控用 Rust；只在 libsrt、NVIDIA SDK 和 libxaac 边界使用 C FFI。

不可信媒体数据需要大量长度、状态和生命周期处理，Rust 可以把越界、释放后使用和数据竞争风险限制在小范围。外部库已经拥有成熟能力，没有必要为了“纯 Rust”重新实现 SRT 或硬件 codec。

**没有选择**把整个主链写成 C/C++，也没有把 FFI handle 散落到业务代码。代价是需要维护安全 wrapper 和构建脚本；收益是 unsafe 可审计、后端可替换。

## 复用 libsrt

**决定**：可靠传输、加密、Stream ID、拥塞控制和丢包恢复使用 libsrt 1.5.5。

传输协议的正确性和互操作性比代码归属更重要。自行实现 SRT 不会提高导播差异化，却会引入安全、网络公平性和兼容风险。

**没有选择**自研 UDP 可靠层。代价是接受 MPL-2.0 组件、CMake/OpenSSL 构建和原生库升级工作。

## 独立实现 MPEG-TS

**决定**：在公开规范基础上实现项目所需的 PAT、PMT、PES、PCR、H.264 Annex-B 和 AAC ADTS 子集。

TS 子集边界明确，并直接决定节目时钟、切镜连续性和错误恢复。掌握这一层能避免引入 `libavformat` 运行时，也能对每个输出时间戳做确定性验证。

**没有选择**完整实现所有 DVB/ATSC/字幕/多节目扩展。代价是初期格式覆盖有限，需要 fuzz 和互操作测试。

## 两个持续解码器、一个节目编码器

**决定**：两路机位始终 NVDEC，切镜后把选定 NV12 surface 送入唯一 NVENC。

如果只解码当前机位，切换时要重新启动解码并等待 IDR；如果两路各自编码再拼压缩包，会带来 SPS/PPS、参考帧和时间戳不连续。双解码保证候选画面随时可用，单编码保证接收端看到的是一个连续 H.264 sequence。

代价是持续占用两个解码会话和 surface pool，但比使用两个编码会话更节省关键 NVENC 资源。

## 独立节目时钟

**决定**：输入 PTS 只映射到内部 timeline，输出 PTS/DTS/PCR 由单独的单调时钟产生。

摄像机重启、网络重连、时间戳回绕或两个设备时钟速度不同都会破坏直接拼接。独立时钟让切镜只改变“选择哪一帧”，不改变节目时间的前进方式。

代价是必须设计丢帧、重复帧、音频采样计数和漂移校正策略。

## 所有队列有界

**决定**：容量由 `bufferMs`、帧率和音频块大小计算，并设置硬上限；过载时按节点策略丢旧数据、标记不健康或失败。

直播不能靠“把延迟和内存越堆越高”隐藏处理不及时。固定容量让最坏内存、延迟和故障行为可解释。

**没有选择**通用无界 channel。代价是需要对每种队列明确选择丢弃策略。

## 确定性导播拥有最终决定权

**决定**：健康度、同步、最短镜头、迟滞、冷却和人工控制都由状态机执行。AI 只提交带期限和置信度的分数。

模型会超时、限流、返回无效 JSON，也可能给出不合适建议。直播主链必须在没有任何模型时继续工作，并能解释为什么切镜或拒绝切镜。

代价是 AI 不能绕过规则做“惊喜”镜头；收益是直播安全和可回放测试。

## 音频先解码为 PCM 再切换

**决定**：两路 AAC 都持续解码，进行响度匹配、80ms 等功率交叉淡化和 true-peak 限制后，再统一编码。

直接拼 AAC packet 无法安全完成采样级淡化，还可能改变 AudioSpecificConfig、时间戳和编码器延迟。PCM 是进行听感连续处理的正确层级。

代价是增加解码、DSP 和重新编码成本。

## Docker-first、Linux + NVIDIA

**决定**：核心可以在普通 Linux CI 编译；真实数据面以 NVIDIA Container Toolkit 的 GPU 容器为标准环境。

固定 OS、驱动和 GPU API 能降低个人项目的组合爆炸。原生 SDK 文件不提交仓库，构建时由用户提供并验证版本。

**没有选择**首发 Windows、macOS、AMD 和 Intel。代价是用户范围较窄；收益是可建立一个真实可靠的硬件基线。

## Unix Socket 先于 HTTP

**决定**：第二阶段用权限为 `0660` 的本机 Unix Socket 提供 `take`、`auto` 和 `state`。

它足以支撑控制台 sidecar 和自动化验证，延迟低，并避免过早引入网络监听、TLS、鉴权、租户和 API 服务生命周期。

远程 HTTP/WebSocket 在 Beta 增加，届时映射到同一个内部控制命令，不重新实现导播逻辑。
