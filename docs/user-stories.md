# 用户故事

用户故事是发布门槛。每个故事按“前提—操作—期望—异常”验收；接口、mock 或文档
完成不等于真实用户工作流完成。

## 用受管媒体作业替代 FFmpeg 子进程

**前提**：直播后端开发者当前用 FFmpeg 命令、Shell 和进程守护完成 SRT 转码。

**操作**：把输入、目标 H.264/AAC 参数、延迟和重连策略写成 MediaJob，先执行
`aimedia explain`，再启动作业。

**期望**：启动前看到 codec、GPU、内存域、队列和未满足能力；运行后通过结构化状态
获得帧数、丢帧、重连和资源水位，不再解析 FFmpeg stderr 判断健康。

**异常**：格式、GPU session 或显存不满足时，在发布节目之前拒绝；错误指出哪个能力
不足，不能启动数分钟后才模糊失败。

## 直播输入归一化并发布到平台

**前提**：现场输入来自 RTSP 摄像机或远程 SRT，平台只接受 H.264/AAC RTMPS。

**操作**：声明输入和平台输出目标，不手工选择每一个解码、缩放、重采样和编码节点。

**期望**：图编译器选择可用硬件路径，输出满足平台分辨率、帧率、GOP 和音频要求；
平台密钥不进入 URI 明文和日志。

**异常**：输入断流时输出保持连续；平台拒绝连接时区分 DNS、TLS、鉴权和媒体格式
阶段，输出故障不拖慢输入或其他输出。

## 一次处理后发布多个目标

**前提**：同一直播需要同时推往主平台、备份 SRT 和内部 AI 服务。

**操作**：在一个作业中声明多个输出和一个分析 Tap。

**期望**：输入只解码一次；共享处理结果后按输出要求编码，任何输出都有独立有界队列
和重连计数。

**异常**：一个平台限速或断线时只丢弃该输出的历史数据，不能让其他输出延迟持续增长。

## AI 开发者接入实时音视频

**前提**：开发者要做字幕、审核、商品识别或精彩片段检测，但不熟悉 MPEG-TS 和 GPU
解码细节。

**操作**：订阅抽样视频帧、PCM、时间和质量事件，返回带时间、置信度和有效期的结果。

**期望**：AI SDK 负责采样、资源释放和 deadline；分析事件能关联到节目时间，但不能
直接修改输出时间戳。

**异常**：模型变慢、返回非法数据或崩溃只增加对应指标；实时媒体主链继续运行。

## 运维人员管理长期直播

**前提**：作业部署在 Linux Docker + NVIDIA 环境，需要连续运行数小时或数天。

**操作**：观察输入、codec、GPU surface、队列、时间、输出和事件指标，并注入断网、
坏 TS、GPU OOM 和输出拒绝。

**期望**：所有队列有硬上限；重连、decoder reset、IDR 请求和丢帧都有稳定原因码；
ready 表示节目真实可输出，而不只是进程存在。

**异常**：GPU device lost、OOM 或编码器不可恢复错误明确终止作业，禁止静默 CPU 回退
或持续输出损坏数据。

## 开源贡献者扩展能力

**前提**：贡献者可能没有 NVIDIA GPU、libsrt、libxaac 或专有 SDK。

**操作**：在默认 workspace 运行图编译、fake backend、parser、replay 和 fuzz；需要时
实现独立 transport、codec 或 analyzer adapter。

**期望**：普通 CPU 环境可验证核心；`crates/` 下目录使用 `core`、`graph`、`runtime`
等短名称，公开 Cargo 包仍保留 `aimedia-*`；native unsafe 代码集中在边界 crate。

**异常**：启用 GPU feature 但缺少 SDK 时，构建明确列出缺失文件和准备方式。

## 自动导播扩展示例

**前提**：用户确实有两路同步输入，需要语音、人物和健康度驱动的自动切换。

**操作**：在通用媒体作业上启用 director policy 和 Analyzer Tap。

**期望**：确定性规则拥有最终决定权，人工 Take 优先；策略只控制 timeline 选择，不
拥有 transport、codec 或输出时钟。

**异常**：分析器、VLM 或策略失败时退回当前健康输入；它们不是媒体输出的存活条件。
