# v0.2 Native Live Pipe 性能与稳定性报告

本报告记录单路原生 SRT 数据面的发布门禁，不把短跑、mock 或 FFmpeg 子进程当成
aimedia 运行时能力。原始汇总由 `tools/soak.ps1` 生成，测试端工具与运行镜像隔离。

## 被测链路

```text
FFmpeg 测试源 -> SRT/MPEG-TS -> aimedia
                                NVDEC H.264
                                libxaac AAC decode/encode
                                独立节目时钟
                                NVENC H.264
                  aimedia -> MPEG-TS/SRT -> aimedia probe
```

aimedia 运行时不包含 `ffmpeg`、`ffprobe` 或 `libav*`。FFmpeg 只在独立测试镜像中生成
1080p30 彩条和 997Hz 音频。

## 这次修复了什么

早期实现把 `bufferMs` 当成每条串行边都能填满的目标，实际总延迟会被多次相加；随后
使用 `keepLatest` 虽然避免了 NVDEC surface 205，却会在 SRT 突发交付时替换有效帧。
最终实现采用：

- `bufferMs` 是整个引擎路径的上限预算，主链物理队列容量为 1；
- 视频时间线使用有界 backpressure，不靠丢帧维持低延迟；
- 视频和音频解码前取得消费许可，避免生产者手里再隐藏一个未计入水位的 decoded frame；
- 输入 transport 在接收前预留队列位置，避免队列之外再持有一个消息；
- 节目 ticker 使用 burst 补齐错过的 tick，并在首帧到达时建立相位；
- 运行时使用有界延迟直方图，probe 同时验证 PTS、DTS 和 PCR。

延迟 output listener 的独立回归也通过：延迟 4 秒连接后，三端退出码为 0，视频丢帧为
0，surface 高水位 3/4，首包 IDR 且 PTS/DTS 单调，没有再出现 NVDEC 205。

## 结论与边界

这次结果满足 v0.2 在 RTX 5060 Laptop 上的 1080p30 两小时发布门槛，证明支持范围内的
单路 SRT/H.264/AAC 原生链路可以进入版本发布。它不证明 RTMP、RTSP、H.265、缩放、
变帧率、双路导播、NVIDIA L4 或 24 小时生产稳定性；这些能力仍按路线图分别验证。
